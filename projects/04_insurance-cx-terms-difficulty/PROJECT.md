## 4. 고정 규칙

### 4-1. 결과 판정 (`cited`)
- 인용·일부 인용 = 1, 기각 = 0. 각하·취하·조정 불성립 등 본안 판단이 아닌 것은 제외(`exclude_reason`).
- 주문 표현별 판정표는 **파일럿 후 3명이 확정**하고 여기 4-8에 붙인다. 확정 뒤 바꾸지 않는다.
- 어디에도 안 맞으면 `needs_review = 1`.

### 4-2. 쟁점 조항 추출
1. 기본은 **위원회 판단 부분**만 사용(주 분석 전환 시 당사자 주장 부분).
2. "약관/보통약관/특별약관/이 사건 약관"이 붙은 `제○조`만 약관 조항으로 인정.
3. **법령 조문은 제외**: 상법, 약관의 규제에 관한 법률(약관규제법), 보험업법, 민법 등.
4. 여러 개면 **처음 언급된 조항**.
5. 문구는 **붙임 약관**에서. 없으면 결정문 안에 옮겨 적힌 조문 문구(최근 결정은 "1. 기초 사실 – 보험약관", 옛 결정은 "위원회 판단 – (1) 관련 약관 규정")를 쓴다(`clause_text_source = 본문 인용`). 둘 다 없으면 `exclude_reason = "조항 문구 없음"`.
6. 조항을 못 찾으면 `exclude_reason = "조항 미추출"`.

### 4-3. 조항 단위 (`clause_level`)
- 호까지 나오면 그 호만, 항까지 나오면 그 항만, 조만 나오면 조 전체.

### 4-4. 부정 표현 처리
- `explained_duty`: 0 미언급 / 1 위반 인정 / 2 위반 불인정
- `ambiguity`: 0 미언급 / 1 모호함 인정 / 2 모호하지 않다고 부정. **예측변수로 쓰지 않는다.**
- 키워드 뒤 형태소에 "없", "아니", "않", "이행하" 등이 있는지로 판별. 애매하면 `needs_review = 1`.
- 이것은 감성분석이 아니다. **감성분석은 쓰지 않는다.**

### 4-5. 쟁점 유형 (`issue_type`)
- 2~3개 범주(예: 면책 / 고지·설명 / 보상 범위·정의). 정확한 범주는 파일럿 후 확정해 4-8에 붙인다.

### 4-6. 중복 제거
- 회귀 표본은 **결정례만**. 분쟁조정 사례(160건)는 참고용(담보 분포, 정성 보조 인용).
- `case_key`(조정번호)가 같은 행은 하나만.

### 4-6-1. 게시물과 결정문
- 게시물 하나에 결정문(hwp)이 여러 개 붙은 경우가 있다(445건 중 3건). **분석 단위는 게시물이 아니라 결정문 1건(조정번호)** 이다.
- 첨부가 hwp가 아닌 파일은 다음과 같이 처리한다(2026-11-03 확정).
  - **pdf**: 글자를 뽑을 수 있는 pdf는 텍스트로 변환해 **포함**한다. 해당 결정문은 제2022-5호(nttId 64819) 1건이다. 다른 pdf 1개(64766)는 사례집이라 아래 규칙으로 이미 제외된다. 변환 도구는 case-parser가 제안하고(예: pdfplumber 또는 poppler의 pdftotext), `requirements.txt`에 추가한 뒤 쓴다.
  - **tif**(2개, 64666·64667): 스캔 이미지라 글자를 바로 뽑을 수 없으므로 `exclude_reason = "지원하지 않는 형식"`으로 제외하고 한계에 적는다. OCR은 쓰지 않는다.
- **결정례가 아닌 게시물은 제외**한다: 제목에 "사례집"이 들어간 게시물(nttId 64709, 64766). `exclude_reason = "결정례 아님"`. 전체 다운로드에서도 받지 않는다.
- **배포용(보호) 문서**는 본문을 추출하지 않고 제외한다(`exclude_reason = "배포용 문서"`). 작성자가 복사·편집을 막아 둔 문서라, 보호를 풀어 읽는 것은 저작권법상 기술적 보호조치를 피하는 일이 될 수 있다. 전체 변환에서 19건(모두 2010~2016년)이 해당했다. 1차 변환 때 생긴 안내문 txt 19개는 `texts/`에 남아 있으니 `decisions.csv`의 `오류`가 빈 행의 txt만 읽는다. 제외 사건 점검(기준값 11)에 포함하고 한계에 적는다.
- 옛 결정(특히 1998~2009년)은 **주문 항목이 없는 경우가 많다**(신청취지 → 이유 → 판단 → 결론 순). 이때 결과는 `결론`으로 판정한다. 결정일도 대부분 없어서 **조정번호의 연도**로 시기 구간을 정한다.
- **한글 3.0 형식**(2000~2001년 결정 일부)은 LibreOffice로 변환한다(`hwp_batch.py`가 자동으로 사용). LibreOffice가 없으면 "한글 3.0 형식 — LibreOffice 설치 필요"로 기록된다.
- **결정일(`decision_date`)은 hwp 안의 조정일자**(`decisions.csv`)에서 가져온다. 상세 페이지 본문의 결정일 문장은 최근 게시물 몇 건에만 있어서 쓰지 않는다. hwp에 조정일자가 없으면 조정번호의 연도(`fss_details.csv`의 `year`)로 구간만 정하고, 그것도 없으면 등록일 연도를 쓰되 `needs_review = 1`로 표시한다.
- 사이트의 하위 분류(손해보험/자동차보험/보험기타/금융투자기타)는 그대로 쓰지 않는다. "금융투자기타"로 표시된 211건도 내용은 생명보험 등 보험 건이다. 상품 구분이 필요하면 안건명·본문으로 다시 분류한다.

### 4-6-2. 자동차보험 제외 (기준값 17)
- **`is_auto = 1`(제외)**: 분쟁 대상 계약이 **자동차보험**(개인용·업무용·영업용 자동차보험, 대인·대물배상, 자기신체사고, 무보험자동차 상해 등 자동차보험의 담보)인 경우.
- **판정 근거는 결정문 본문**(기초 사실의 보험 종목, 쟁점 담보)이다. 사이트 분류와 제목은 참고만 한다.
  - 사이트 분류 "자동차보험"(81건)은 파일럿 표본에서 미리 뺀다(`site_auto`).
  - 제목에 "자동차보험, 자배법, 자동차손해배상, 대인배상, 대물배상, 무보험자동차, 자기신체사고"가 있으면 후보(`auto_candidate`)로 표시하고 본문으로 판정한다.
- **포함(`is_auto = 0`)으로 보는 예**: 교통사고라도 상해·생명보험의 재해 인정, 운전자보험(형사합의금 등), 실손의료보험의 보상 범위 다툼(제목에 "자동차보험"이 있어도).
- 애매하면 `needs_review = 1`. 제외한 건은 `exclude_reason = "자동차보험"`으로 건수를 기록한다.
- 분쟁조정 사례 160건에도 같은 기준을 적용한다.

### 4-7. 가림 규칙
- 파일럿에서는 **분포만** 본다(인용·기각 비율, 추출 비율, 시기별 변환 성공률 등).
- **난이도와 결과의 관계는 규칙이 모두 확정되기 전에 계산하지 않는다.**
- 파일럿용 난이도 입력 파일에는 **`cited` 열을 넣지 않는다.**
- 난이도 평가 시트에는 사건 번호·결과·시기를 넣지 않는다.

### 4-8. 파일럿 후 확정 규칙 (2026-11-03 팀 확정, 결과를 보기 전)
근거: `docs/파일럿_라벨보고.md`, `outputs/stats/difficulty_pilot_요약.md`, 회의 안건 문서. 모두 추천안대로 확정했다.

- **주문 표현별 판정표**: "청구를 기각한다" → `cited = 0`. "보험금을 지급하라", "보험계약을 부활하라", "보험료를 환급하라", "보험기간을 인정하고…", "해지처리를 취소하고…"처럼 고객 요구를 들어준 명령 → `cited = 1`. 주문이 없으면 `결론`으로 판정하고 `needs_review = 1`. 각하·취하·조정 불성립 → 제외(`exclude_reason`). 그 밖의 표현 → `needs_review = 1`.
- **일부 인용 구분 규칙**: `partial` 열(0/1)을 둔다. (가) 결론·주문에 "일부인용/일부 인용"이 명시되면 자동으로 `partial = 1`. (나) 주문은 이행 명령인데 결론에 일부 배척 표현("…하지 않으나", "…어려우나", "이유가 없다고 할 것이나")이 있으면 `needs_review = 1`로 사람이 신청취지와 대조. (다) 신청취지와 주문 문구가 다르기만 한 경우는 `partial_hint = 1` 표시만 하고 needs_review로 올리지 않는다. 일부 인용도 `cited = 1`이다(필수 민감도 ①에서만 0).
- **쟁점 유형 범주**: 3개 — `면책`("보상하지 아니하는/않는", "지급하지 아니하는/않는", "면책"), `고지·설명`("알릴의무", "고지", "설명의무"), `보상범위·정의`(나머지). 배정: **안건명**에 키워드가 있으면 안건명으로, 없으면 **추출한 조항의 조 제목**으로, 둘 다 없으면 `보상범위·정의`.
- **부정 표현 사전**: 보고서 7장 후보 키워드·판정 규칙에 **제외 맥락**을 더한다. 다음 문장은 판정에 쓰지 않는다: 당사자·설계사 주장("주장하", "다투고"), 법령·판례 인용("판시", "선고", "○○법 제○조", "법률 제○조"), "가./나./다."로 시작하는 짧은 소제목 줄. 위원회의 이 사건 결론 문장만 1/2를 만든다. 원칙 문장은 같은 문장이나 다음 문장에서 이 사건 조항에 적용할 때만 1. "소결"·결론 문단의 판정이 앞 문단과 다르면 소결을 따른다. `ambiguity`는 보험약관 조항의 모호함만 1(증권·청약서·안내장은 0). 판정 기준 전체는 4-8-1과 같다.
- **조 제목 주제 합치기 규칙**: 공백·괄호를 지운 조 제목(없으면 안건명)에 아래 키워드가 있으면 위에서부터 처음 맞는 주제로 `topic`을 붙인다. 계약 전 알릴 의무(알릴, 고지) / 면책(보상하지, 지급하지, 면책) / 계약 해지·부활(해지, 부활, 효력) / 보험기간·갱신(보험기간, 갱신) / 장해(장해) / 수술·입원 정의(수술, 입원) / 질병 정의(암, 질환, 진단) / 재해·상해 정의(재해, 상해, 사고) / 보험금 지급사유(지급사유, 보상하는) / 기타. 본 실행 뒤 "기타"가 20% 이상일 때만 키워드를 보태고 변경 기록에 남긴다.
- **주 분석 조항 추출 위치 판정 결과**: **판단 기반**(기준값 8: 주장 추출 1/26 = 3.8% < 60%).
- **조항 추출 보완**: ① 위원회가 풀어 쓴 서술만 있는 조항(`clause_text_form = 풀어 쓴 서술`)은 **주 분석에서 제외**(`exclude_reason = "풀어 쓴 서술"`)하되 문구는 남겨 선택 민감도("풀어 쓴 서술 포함")로 보고한다. ② 약관 표지에 '특약'("이 사건 특약 제1조")을 포함한다. ③ 판단이 조 번호 없이 별칭("이 사건 면책사유")으로 가리키고 조문이 붙임·기초 사실에 있으면 사람이 연결하고 `clause_source = "수동 연결"`, `needs_review = 1`. 별표도 같다. ④ "처음 언급 조항" 규칙은 그대로 두고, "쟁점 문장에 가장 가까운 조항"은 선택 민감도로만.
- **구간 합치기·제외 판정 결과**: 제외 구간 없음(파일럿 변환 성공률 ~2009 9/9, 2010~2016 9/9, 2017~2026 9/9, pdf 포함 후). 합치기(기준값 5, 30건 미만)는 본 실행 뒤 구간별 분석 사건 수로 판정한다.
- **진행 여부 판정 결과**: **진행**. 계획서 14-2 기준을 모두 넘는다: 변환 성공률 100%, 판단 기준 추출 80.8%(풀어 쓴 서술 제외 시 53.8%), 추정 분석 사건 약 188건(150건 이상), 기각 추정 약 51건(30건 이상), 결과 판정 needs_review 4/26 = 15.4%(20% 미만), 부정 표현 사건 단위 일치 47/52 = 90%(85% 이상). "150건"은 진행 판단에만 쓰고, 회귀를 탐색적으로 낮추는 기준은 기준값 10(적은 쪽 30건)을 따른다.
- **난이도 지표 설정**(`outputs/stats/difficulty_colab.py` [고정 설정]): 예외 표현 사전은 **확장판**(v7 + "불구하고", "아니합니다", "않습니다" 등). 0이 50%를 넘어도 개수 그대로 쓰고, 본 분석에서도 0이 50% 이상이면 한계에 적는다. "제외" 뒤에 "금액"이 붙은 명사(보장제외금액 등)는 세지 않는다. 참조 표현은 **개별**(제3조 제2항 = 2개). 전문용어 사전에서 흔한 말 5개(회사, 계약, 의사, 약국, 입원)를 빼서 36개로 쓴다. 표준약관 3종은 생명보험 + 질병·상해보험 + 실손의료보험.
- **평가 시트 표본**: 파일럿 27건과 20건 대조 표본에서 **뺀** 사건 중 시기별로 고르게 25개(시드 42). 대조하며 결과를 본 사건을 평가하지 않게 하기 위해서다.
- **난이도 입력의 가림**: 본 분석도 파일럿처럼 임시 번호(`diff_id`)를 쓰고, `diff_id`↔`case_key` 대응표는 정유빈이 보관했다가 stats 단계에서 팀원B에게 넘긴다.
- **분쟁조정 사례 160건**: 본문을 받지 않으므로 자동차 판정은 사이트 유형("자동차보험(…)") 기준으로 하고, 제목에 자동차 관련어가 있으면 본문을 확인한다(4-6-2의 "본문 기준"은 결정례에만 적용). 유형이 "보험(…)"뿐인 16건은 담보 분포에서 "보험(종류 미상)"으로 따로 묶는다.

- **코드북·지표 정의**: `docs/코드북.md`(유형마다 이름·정의·포함·제외·예, 지표마다 분자·분모·기간·제외 조건). 규칙은 4장과 같고 표로 옮긴 것이다.
- **결론 형식**: 주요 결과마다 **관찰 → 해석 → 권고**. 관찰에는 분모와 기간을 함께 쓴다. 해석은 연관성까지만, 권고는 근거가 있는 만큼만(계획서 13장).
- **민감 내용**: 신청인의 질병·진단명·복용약·계좌 등이 들어간 문장은 인용하지 않고 집계로만 쓴다. 대시보드 사례 뷰어는 약관 조항 문구, 난이도, 결과, 출처만 보여 준다.
- **한계에 추가**: ① 표본은 분쟁조정을 신청했고 결정문이 공개된 사건뿐이다(소송·합의·민원 단계에서 끝난 분쟁, 비공개 결정, 자동차보험은 없다). ② 결정문 양식이 시기마다 달라(옛 결정은 풀어 쓴 서술이 많음, 풀어 쓴 서술 91건 중 54건이 2009년 이전) 시기별 차이를 실제 변화로 단정하지 않는다. ③ 결정문에 고객 정보가 없어 고객 집단(연령 등) 비교는 하지 않는다.
- **발표 질의응답 준비**: "이 수치는 어떻게 구했나"(지표 정의표, 코드), "이 데이터에 없는 고객은 누구인가"(위 한계 ①), "분석 단위를 바꾸면 결론이 달라지나"(조 전체 지수·필수 민감도 결과).
- **배포**: 대시보드는 단일 HTML을 GitHub Pages로 배포해 로그인 없이 열리게 한다. 완성 전(목요일)에 한 번 시험 배포하고, 발표 전 로그인하지 않은 브라우저·다른 기기에서 열리는지 확인, 캡처를 준비한다. 시험 배포 전에 `.gitignore`(원문, 대응표, 백업, 발췌가 있는 파일 제외)를 먼저 만든다.
- **노션**: 팀원C이 정리(writer 작업 4 초안 사용). 결정과 이유는 PROJECT.md 4-8과 변경 기록을 옮긴다.

## 6. 수집·저작권 원칙

- 로그인, 차단 우회를 하지 않는다. 막히면 멈추고 `docs/수집근거표.md`에 기록한다.
- 금감원 저작권 정책: 무단 복제·배포 원칙적 금지, 교육·연구 목적의 정당한 인용과 비영리 이용 허용, 자동 수집 금지 문구 없음. robots.txt는 일반 로봇과 결정례 경로를 막지 않음(2026-10-30 확인).
- 따라서: **원문 재배포 금지**, 대시보드·발표에는 분석 결과와 **짧은 인용(2~3문장)** 만, 출처는 "금융감독원 분쟁조정결정례 제○호", 인용문은 바꾸지 않는다.
- 게시물의 **작성자·담당자 이름, 이메일, 전화번호는 수집하지 않는다.** 결정문 속 당사자 실명 등이 보이면 저장하지 않고 보고한다.
- 법적 판단은 에이전트가 내리지 않는다. 근거를 정리해 팀에 넘긴다.

## 7. 일하는 방식 (모든 에이전트 공통)

- 입력은 지정된 파일만, 출력은 지정된 파일만.
- 모르는 것은 **"미확인"** 으로 적는다. 추측으로 채우지 않는다.
- 숫자는 **코드로 계산**하고 코드와 결과 파일을 함께 남긴다. 암산 금지.
- 파이썬은 `requirements.txt` 환경에서 실행한다. 새 라이브러리가 필요하면 설치하지 말고 추가를 제안한다.
- 규칙을 바꾸고 싶으면 바꾸지 말고 **"규칙 변경 제안"** 으로 보고만 한다.
- 결과가 기대와 달라도 분석을 추가하거나 변수를 바꾸지 않는다.
- 인과 표현(때문에, 영향을 줬다)을 결론으로 쓰지 않는다. "관련이 있는 경향", "함께 나타난다".
- 작업이 끝나면 맨 위에 4줄 요약: **한 일 / 처리 건수 / 제외한 것 / 불확실한 점**. 그리고 사람 확인 지점이면 멈춘다.

## 9. 검수 체크리스트 기본 항목 (`docs/검수체크리스트.md`의 뼈대)

- [ ] 라벨(`cited`, `issue_type`, `explained_duty`, `ambiguity`)이 원문과 맞는가
- [ ] 법령 조문이 약관 조항으로 섞이지 않았는가
- [ ] 제외 사유 건수 합이 맞는가(전체 = 분석 포함 + 제외)
- [ ] 파일럿에서 난이도와 결과의 관계를 계산하지 않았는가
- [ ] 평가 시트에 사건 정보·결과가 새지 않았는가
- [ ] 통계 코드를 다시 돌리면 같은 숫자가 나오는가
- [ ] 모든 결과에 오즈비·예측 확률·95% 신뢰구간·N이 있는가
- [ ] 필수 민감도 4개가 모두 보고되었는가
- [ ] 보고서·대시보드의 모든 숫자에 출처 파일이 있는가
- [ ] 인과 표현이 없는가, 불확실성 문구가 지워지지 않았는가
- [ ] 결정문 인용은 짧고 출처가 표시되었는가, 개인정보가 없는가
