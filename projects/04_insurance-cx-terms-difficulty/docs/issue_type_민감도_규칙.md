- **주 분석은 바꾸지 않는다.** 주 모형·필수 민감도는 사전 규칙(R1, 코드북 Q4–Q5)의 `issue_type`을 그대로 쓴다. R2는 선택 민감도 1줄(사후, 탐색적)로만 쓴다.

## R1 (사전 규칙, 그대로)

안건명 키워드 → 없으면 위원회 판단에서 **처음 언급된** 약관 조항의 조 제목 키워드 → 없으면 보상범위·정의.

## R2 (사후 민감도용)

1. 안건명에 키워드가 있으면 그 유형(R1과 같음).
2. 없으면 위원회 판단 본문(`decisions.csv`의 `위원회_판단`, 붙임 제외)에서 약관 조 제목 `제○조(…)`를 **모두** 찾는다. 괄호는 ( ) 【 】 [ ] 〔 〕 < > 를 인정한다. 바로 앞에 법령 이름(…법, 시행령, 시행세칙, 규정)이 붙은 조문은 뺀다.
   - 처음 나온 조 제목에 키워드가 있으면 그 유형(R1과 같음).
   - 아니면, 나머지 조 제목 중 **하나라도 면책 키워드**가 있으면 **면책**.
   - 아니면, 하나라도 고지·설명 키워드가 있으면 **고지·설명**.
3. 둘 다 없으면 보상범위·정의.

키워드는 코드북과 같다. 면책: 보상하지 않는/아니하는, 지급하지 않는/아니하는, 면책. 고지·설명: 알릴의무, 고지, 설명의무. 공백은 지우고 찾는다.

### 구현 보충 (2026-11-04 16:08, 골드 적용 전)

- 위 2번을 새 코드로 그대로 짜면 조 제목 찾기 방식이 case-parser와 조금 달라 **R1 값부터 157건 중 6건이 달라졌다**(제목 표기가 `제○조` 꼴이 아닌 사건 등). R2는 "R1에 한 단계를 보탠 것"이어야 하므로 구현을 이렇게 정한다.
  - **R1 값이 면책·고지·설명이면 그대로 둔다.**
  - **R1 값이 보상범위·정의일 때만** 위 2번의 "나머지 조 제목" 확인(면책 → 고지·설명 순)을 한다.
- 규칙의 뜻은 바뀌지 않는다. 골드와 결과는 이 보충을 적은 뒤에 처음 본다.
