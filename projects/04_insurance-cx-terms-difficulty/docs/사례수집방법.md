# 분쟁조정 사례 160건 수동 수집 방법

작성: 팀원C(C) · 2026-10-30
근거: `PROJECT.md` 2장(`data/raw/cases_summary/`), 4-6(사례는 참고용), 6장(수집·저작권 원칙), `HANDOFF.md` 3장·7장

---

## 1. 무엇을, 왜 모으나

- **무엇:** 금융감독원 홈페이지 "분쟁조정사례" 게시판의 **보험** 사례(요약문).
- **왜:** 회귀(주 분석)에는 넣지 않는다. 두 가지 보조 용도로만 쓴다(`PROJECT.md` 4-6, `agents/writer.md` 작업 1-5).
  1. **담보 분포**: 어떤 보험·담보에서 분쟁 사례가 많이 소개됐는지를 결정례와 **나란히**(합치지 않고) 비교
  2. **정성 보조**: 대표 사례를 설명할 때 참고
- **결정례와 다르다:** 결정례는 정유빈(A)만 받는다. 이 문서는 결정례 수집이 아니다.

## 2. 어디서

| 항목 | 내용 |
|---|---|
| 메뉴 | 금감원 홈페이지 → 민원·신고 → 분쟁조정정보 → **분쟁조정사례** |
| 거르기 | 권역 = **보험** 선택 → 검색 |
| 건수(2026-10-30 확인) | 보험 **160건**(16페이지). 게시판 전체는 201건(다른 권역 포함) |
| 목록 열 | 번호, 권역, 유형(예: "실손보험(치료비)"), 제목, 등록일, 상세내용(첨부), 카드뉴스, 조회수 |

※ 결정례 게시판(분쟁조정결정례)과 **다른 게시판**이다. 헷갈리지 않게 주소창에 `fncCnflCase`가 있는지 본다.

## 3. 어떻게 (손으로)

자동 수집 프로그램은 쓰지 않는다. 사람이 브라우저로 보면서 적는다.

1. 보험으로 거른 목록을 1페이지부터 16페이지까지 차례로 연다.
2. 각 줄을 `docs/사례수집_양식.csv` 양식에 한 줄씩 옮긴다. (목록 표를 드래그해서 엑셀에 붙여 넣고 열을 정리해도 된다.)
※ 목록의 "번호"는 게시판 전체 번호가 아니라 **보험으로 거른 목록 안의 순번(1~160)** 이다. 정리본에서는 `list_no`로 부른다. 새 사례가 올라오면 순번이 바뀔 수 있으므로 수집일(2026-10-30)을 함께 기록한다.
3. 유형 칸의 괄호 앞부분은 `product_group`, 괄호 안은 `coverage`로 나눠 적는다.
   - 예: "실손보험(치료비)" → `product_group` = 실손보험, `coverage` = 치료비
   - 괄호가 없으면 `coverage`는 비워 둔다.
4. **정성 보조용 본문**은 전부 받지 않는다. 대표 사례 설명에 쓸 것만 나중에 골라서 읽는다(11/6~11/8). 첨부를 내려받는 경우 `data/raw/cases_summary/files/`에만 두고 밖으로 내보내지 않는다.
5. 다 옮긴 뒤 건수가 160인지, 번호가 빠지거나 겹치지 않았는지 확인한다.
6. 완성 파일은 `data/raw/cases_summary/사례목록_원본.csv`로 저장한다(정리본은 `outputs/qual/사례목록_정리.csv`). 저장 뒤에는 수정하지 않는다(원본).

## 4. 적지 않는 것 (저작권·개인정보)

- 담당부서 직원 이름, 이메일, 전화번호
- 본문 전문(필요한 2~3문장만, 쓸 때 출처를 단다)
- 사례 속 개인 정보가 보이면 적지 않고 팀에 보고

## 5. 자동차보험 사례를 어떻게 할지

- 팀 결정: 자동차보험은 결정례와 사례 모두 **제외**한다(`PROJECT.md` 기준값 17, 4-6-2).
- 원본에는 모두 남기고, 정리본에 `is_auto`를 표시해 분석할 때 뺀다.
- 사례는 본문을 받지 않으므로 다음처럼 판정한다.
  - 유형이 "자동차보험(…)"이면 `site_auto = 1`, `is_auto = 1`.
  - 유형은 자동차보험이 아닌데 제목에 자동차 관련어(4-6-2 목록)가 있으면 `auto_candidate = 1`, `is_auto`는 비우고 `needs_review = 1`. 사람이 그 사례 본문을 읽고 판정한다.
