팀원B이 직접 정한 마무리 4가지다. **주 결과·판정 문구·다른 출력 숫자는 바꾸지 않는다.** `PROJECT.md`, `agents/`, `docs/코드북.md`, `data/`는 수정하지 않는다. 파이썬은 `py -3.10`. 설치·다운로드·삭제·git은 하지 않는다.

## 2. 07_민감도_필수.csv에 firth·exploratory 열 추가

- `analysis.py`를 고쳐 `07_민감도_필수.csv` **맨 뒤에** `firth`(0/1), `exploratory`(0/1) 두 열을 더한다. 값은 각 행 모형에서 실제로 쓴 방식이다(기준값 9: 소수 쪽 50건 미만이거나 분리면 Firth, 기준값 10: 소수 쪽 30건 미만이면 exploratory). ②처럼 수행한 행만 값이 있고, 수행하지 못한 행이 있으면 다른 칸과 같은 문자열을 넣는다.
- 예상: ④ 2010년 이후는 firth = 1, exploratory = 1. 나머지는 0, 0. 다르면 그대로 쓰고 보고에 적는다.
- **기존 열의 값과 다른 모든 csv는 바이트 단위로 그대로**여야 한다. 처음부터 다시 돌려 확인한다.
- `통계요약.md` 필수 민감도 표에도 두 열을 반영한다. 판정 문구는 바꾸지 않는다.
- 보고에 "agents/stats.md 출력 표와 열이 달라졌다(맨 뒤 2열 추가). agents/ 반영은 정유빈에게 요청"이라고 적는다.

## 3. profile.py 이름 바꾸기

- `outputs/stats/profile.py`가 파이썬 내장 모듈 `profile`과 이름이 같아 같은 폴더의 다른 코드가 import에서 깨진다. 이름을 `outputs/stats/difficulty_profile.py`로 바꾼다(내용은 고치지 않는다. 파일 안 주석의 파일 이름과 실행 예시만 새 이름으로).
- `outputs/stats/__pycache__/profile.cpython-310.pyc`는 지우지 않는다(삭제 금지). 이름을 바꾼 뒤에는 쓰이지 않는다고 보고에 적는다.
- `topic.py`의 우회 코드(스크립트 폴더를 import 경로에서 빼는 부분)는 그대로 둔다.
- `difficulty_profile.py`를 한 번 돌려 11~16, 13b, 난이도프로필_요약.md가 **바이트 단위로 그대로**인지 확인한다. 그림(png)은 대조하지 않아도 되지만 덮어쓴다면 보고에 적는다.
- 기존 보고서(`docs/보고/난이도프로필_*.md`, `프로필검수_*.md`)는 고치지 않는다. 대신 이 정리 보고에 "profile.py → difficulty_profile.py로 이름 변경"을 적는다.

## 4. 다음에 바꿀 점 정리 (적용하지 않음)

`docs/보고/다음에_바꿀_점.md`를 새로 만든다. 지금까지 보고서에 나온 규칙 변경 제안을 **적용하지 않은 채로** 한곳에 모은다. 각 항목에 출처 보고서 이름을 붙인다.

- stats: 검수 2의 제안(이번에 1·2번으로 처리한 것은 "처리함"으로 표시)
- 난이도 프로필: 조건 표현이 사실상 "경우", 참조 수와 참조 묶음 수가 거의 같음, top_dim "없음" 136/157 등 정의 쏠림
- BERTopic: 면책 키워드 추가 제안("지급하지 아니", "고의", "자살"), 안정성을 최소 ARI로도 판단, `(2007년조정례)` 같은 표시 제거
- BERTopic 면책 단서 점검의 설계 한계: R1이 안건명 키워드를 먼저 쓰므로 "안건명에 면책 단서가 있는데 면책이 아닌 사건"은 구조적으로 생기지 않는다. 발견 1은 골드셋 비교와 R2 민감도로 확인한다
- BERTopic 안정성: seed 42~46 중 seed 43만 다른 구조(ARI 0.06), 나머지 쌍 0.89~0.94. 미리 정한 평균 기준(0.5)은 통과했으며 기준은 바꾸지 않는다. 보고서에는 "5번 중 4번 같은 구조"로 적는다
- ambiguity 규칙: 판례의 작성자불이익 논리를 이어받은 문장, "명백(2)" 값을 규칙이 못 잡음(골드셋 결과)
