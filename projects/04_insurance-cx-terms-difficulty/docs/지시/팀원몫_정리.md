# 팀원 몫 중 팀원B이 할 수 있는 일 정리 (2026-11-04, 담당 팀원B)

정유빈·팀원C이 할 일 가운데 **팀원B이 대신 해도 원칙에 어긋나지 않는 것**만 한다. 결과물은 대부분 **초안·준비물**이고, 실제 반영(PROJECT.md 기록, agents/ 수정, 재실행 대조, 대시보드 구현, GitHub 업로드)은 담당자가 한다.

**수정 금지**: `PROJECT.md`, `agents/`, `docs/코드북.md`, `data/`, `outputs/stats/`의 기존 결과·코드. 새 파일은 `docs/제안/`과 `outputs/stats/재실행_대조/`에만 만든다.
**파이썬**: `PYTHONIOENCODING=utf-8 py -3.10`. 설치·다운로드·삭제·git은 하지 않는다. 숫자는 파일에서 옮기고 새로 계산하지 않는다(1번의 문구 길이 비교 제외).

## 1. 민감도 ② 큰 변화 1건 문구 확인 자료 (원래 정유빈 확인 사항)

- `stats_수정_1.md`가 말한 "②에서 난이도가 −3.19 내려간 1건"을 `analysis.py`의 ② 계산 부분과 `cases.csv`(`clause_text`, `arg_clause_text`)로 찾는다. 계산을 다시 돌리지 말고, 코드 로직대로 해당 사건을 특정한다(필요하면 ② 부분만 읽기 전용으로 재현해 값만 확인).
- `docs/제안/민감도2_큰변화_확인.md`에 case_key, 판단 문구와 주장 문구(약관 문구만), 두 문구의 어절 수·문장 수·지표 4개, 차이가 왜 생겼는지 한 줄을 적는다.
- **판정은 쓰지 않는다**: 맨 아래에 "팀원B 확인: 주장 문구가 같은 조항의 일부다 / 다른 조항이다 / 잘렸다 (하나 고르기)" 칸만 둔다. 사람이 고른다.

## 2. 재실행 대조 키트 (대조 자체는 정유빈이 한다)

stats를 만든 사람이 대조하면 독립 검수가 아니다(PROJECT.md 검수 원칙). 그래서 대조는 정유빈이 하되, 5분 안에 끝나게 준비한다.

- `outputs/stats/재실행_대조/manifest.csv`: 지금 파일들의 md5. 대상: `01`~`10`, `10_조항주제_기준선.csv`, `pred_curve.csv`, `통계요약.md`, `11`~`16`, `13b`, `난이도프로필_요약.md`, `17`~`22`, `토픽_요약.md`. 열: file, md5, bytes, made_by(analysis.py / difficulty_profile.py / topic.py).
- `outputs/stats/재실행_대조/check.py`: 정유빈이 세 코드를 다시 돌린 뒤 실행하면 manifest와 비교해 "같음/다름/없음"을 표로 출력한다. 다른 파일은 무엇이 다른지(csv면 다른 행 수) 보여준다.
- `outputs/stats/재실행_대조/README.md`: 순서(① requirements 설치, ② `PYTHONIOENCODING=utf-8 py -3.10 outputs/stats/analysis.py`, ③ `difficulty_profile.py`, ④ `topic.py`(임베딩 캐시가 없으면 모델이 필요함을 적기), ⑤ `check.py`), 걸리는 시간, 그림(png)은 대조하지 않는다는 점.
- 지금 상태로 `check.py`를 한 번 돌려 "모두 같음"이 나오는지 확인한다(코드를 다시 돌리지 않고 manifest와 현재 파일만 비교).
