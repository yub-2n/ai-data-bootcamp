# BERTopic 실행 지시 (2026-11-04, 담당 팀원B)

**성격: 탐색적 보조 분석.** 주 결과와 기존 출력은 바꾸지 않는다. 목적은 세 가지다.
1. 사람이 규칙으로 묶은 조항 주제(`topic`, 10개)와 **데이터에서 자동으로 나온 주제**가 얼마나 겹치는지 본다(규칙 분류 점검).
2. "기타"로 묶인 사건과 큰 묶음(보험금 지급사유) 안이 실제로 무엇인지 드러낸다.
3. 골드셋 발견 1(처음 언급 조항과 실제 쟁점이 다름, 면책이 적게 잡힘)을 **안건명**으로 다시 확인한다. 안건명은 금감원이 실제 쟁점을 요약한 제목이라 "실질 쟁점"의 단서가 된다.

**수정 금지**: `PROJECT.md`, `agents/`, `docs/코드북.md`, `data/`의 기존 파일, `outputs/stats/`의 기존 파일(01~16, 13b, 10_조항주제_기준선, pred_curve, 요약 md들, analysis.py, profile.py, difficulty_colab.py, term_dict.csv).
**파이썬**: `py -3.10`. 준비(패키지 설치·모델 다운로드)는 0장에 적힌 것만 에이전트가 직접 한다(2026-11-04 팀원B 허용). 그 밖의 설치·다운로드는 하지 않는다.
**금지 분석**: 토픽을 `cited`와 검정하거나 회귀에 넣지 않는다. 토픽별 인용률은 Wilson 95% CI와 건수를 붙인 **기술통계로만** 보여준다(5건 이상만).

## 0. 준비와 점검 (에이전트가 직접)

1. **패키지**: `py -3.10 -c "import bertopic, sentence_transformers, umap, hdbscan, kiwipiepy, sklearn, matplotlib"`가 실패하면 **아래 명령만** 실행한다(허용된 설치는 이것뿐).
   ```
   py -3.10 -m pip install bertopic sentence-transformers
   ```
   설치 후 다시 import를 확인한다. 기존 패키지 버전(numpy 1.26.4, pandas 2.3.3, scipy 1.15.3, statsmodels 0.15.0, scikit-learn 1.7.2, firthlogist 0.5.0, kiwipiepy 0.24.1)이 바뀌었는지 `py -3.10 -m pip show`로 확인하고, **바뀌었으면 멈추고 보고**한다(기존 stats 재현에 영향). 설치된 bertopic·sentence-transformers·torch·umap-learn·hdbscan 버전을 보고에 적는다.
2. **임베딩 모델**: `py -3.10 -c "from sentence_transformers import SentenceTransformer as S; S('jhgan/ko-sroberta-multitask', local_files_only=True)"`가 실패하면 **이 모델 하나만** 내려받는다(허용된 다운로드는 이것뿐).
   ```
   py -3.10 -c "from sentence_transformers import SentenceTransformer as S; S('jhgan/ko-sroberta-multitask')"
   ```
   내려받기가 실패하면 다른 모델로 바꾸지 말고 에러를 그대로 보고하고 멈춘다. 이후 분석에서는 `local_files_only=True`로만 불러온다.
3. **파일**: `data/interim/cases.csv`(449행), `outputs/stats/10_조항주제.csv`가 있다.
4. 오래 걸리는 설치·다운로드는 끝날 때까지 기다린다(몇 분 걸릴 수 있음).

## 1. 코퍼스 (지금 고정)

| 이름 | 대상 | 글 |
|---|---|---|
| **주 코퍼스: 안건명** | `cases.csv` 중 `is_auto` = 1(자동차보험)과 `exclude_reason` = "중복"을 뺀 행 | `title` |
| 보조 코퍼스: 조항 문구 | 분석 포함 157건(`exclude_reason` 빈 행) | `clause_text` |

- 뺀 건수와 이유를 보고에 적는다. 같은 `case_key`가 여러 행이면 첫 행만 쓴다.
- **안건명 정리(고정 규칙)**: 괄호 속 사건번호(예: `(제2013-34호)`, `(97-16)`, `(2005-1)`)와 앞머리 `(손해보험사례)`, `(보험기타사례)` 같은 분류 표시를 지운다. 사례집처럼 결정례가 아닌 제목이 남아 있으면 빼고 적는다.

## 2. 모형 설정 (지금 고정)

- 임베딩: `jhgan/ko-sroberta-multitask` (한국어 문장 임베딩). 정규화된 임베딩을 `outputs/stats/topic_cache/`에 저장해 재사용한다.
- UMAP: n_neighbors = 10, n_components = 5, min_dist = 0.0, metric = cosine, random_state = 42
- HDBSCAN: 주 코퍼스 min_cluster_size = 8, 보조 코퍼스 5. metric = euclidean, cluster_selection_method = eom, prediction_data = True
- 키워드(c-TF-IDF): CountVectorizer에 Kiwi 명사 토크나이저(NNG·NNP, 두 글자 이상). 불용어(고정): 여부, 경우, 해당, 관련, 사례, 보험, 보험금, 보험계약, 지급, 책임, 인정, 적용, 대한, 사고, 회사
- 토픽 수는 자동(nr_topics = None). top_n_words = 10
- 바깥값(-1) 비율을 적는다. 바깥값을 줄인 버전(`reduce_outliers`, strategy = "c-tf-idf")을 **별도 열**로 함께 만든다. 주 결과는 줄이기 전 값이다.

## 3. 안정성

- random_state 42~46으로 다섯 번 돌려 토픽 배정 간 **조정 랜드 지수(ARI)** 평균·최소·최대를 적는다. 바깥값은 하나의 묶음으로 친다.
- 평균 ARI가 0.5 미만이면 "토픽 구조가 불안정"이라고 요약 맨 위에 적는다. 이 기준은 지금 고정한다.

## 4. 토픽 이름 붙이기

- 토픽마다 키워드 10개와 대표 안건명 3개(BERTopic `get_representative_docs`)를 보고 **2~6단어 한국어 이름**을 붙인다. 이름 붙이는 사람은 이 에이전트이고, 이름 지시 문구와 모델 이름을 보고에 적는다.
- 이름은 키워드와 대표 안건명에 있는 말로만 짓는다. 해석을 더하지 않는다.

## 5. 비교 (주 코퍼스 기준, 기술통계만)

1. **규칙 주제 대비**: 분석 포함 157건에서 BERTopic 토픽 × 규칙 `topic` 교차표, ARI, 정규화 상호정보량(NMI). 규칙 주제 "기타"와 "보험금 지급사유"가 어떤 BERTopic 토픽으로 나뉘는지 따로 적는다.
2. **쟁점 유형 대비**: BERTopic 토픽 × `issue_type` 교차표(157건).
3. **면책 단서 점검(골드셋 발견 1 확인)**: 정리한 안건명에 `면책`, `보상하지 않`, `지급하지 않`, `면책사유`, `책임이 없` 중 하나라도 있는 사건을 센다. 규칙 `issue_type`별로 이 단서가 있는 건수와 비율을 표로 만든다(특히 issue_type ≠ 면책인데 단서가 있는 건수). 이 키워드 목록은 지금 고정하고, 안건명만 본다.
4. **토픽별 인용률(기술통계)**: 분석 포함 사건이 5건 이상인 토픽만 인용률과 Wilson 95% CI, 건수. 검정하지 않는다.
5. **보조 코퍼스(조항 문구)**: 같은 방식으로 돌리고 토픽 수, 바깥값 비율, 규칙 주제 대비 ARI·NMI만 요약한다. 조항 문구는 비슷한 표준 문장이 많아 토픽이 적게 나올 수 있다는 점을 적는다.
