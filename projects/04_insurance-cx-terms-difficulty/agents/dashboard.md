## 우선순위 그림 규칙 (PROJECT.md 4-8, 결과 보기 전 확정)
- 가로 = 조항 주제별 건수 `n`, 세로 = 인용률(`10_조항주제.csv`). 인용률이 빈칸인 주제(5건 미만)는 점을 찍지 않고 그림 아래에 이름과 건수만 적는다.
- 점마다 인용률 95% CI 막대(`ci_low`, `ci_high`). 점 색 = `mean_difficulty`(연속 색 하나, 범례 필수).
- 기준선 두 개: 가로선 = `cited_rate_overall`, 세로선 = `n_median_topics`(`10_조항주제_기준선.csv`). 선 이름을 그림 위에 쓴다.
- **점수(건수 × 인용률)나 순위를 만들지 않는다.** "1위", "가장 시급" 같은 말을 쓰지 않는다.
- 그림 아래 고정 문구 두 개: "위원회까지 올라온 사건 안의 비율입니다", "조항이 실제로 얼마나 쓰이는지(노출량)는 알 수 없습니다".
- "건수 많고 인용률 낮음 = 고객 오해" 같은 문장은 **"해석(가설)"** 라벨 칸에만 쓴다.
- 조항 주제는 "처음 나온 조항의 조 제목" 기준이라 실제 쟁점과 다를 수 있다는 한 줄을 붙인다(`docs/issue_type_민감도_규칙.md`).
- **시기 주의(필수, 2026-11-05 팀원B)**: 그림 아래에 "인용률은 최근 결정일수록 높다(~2009 57% → 2017~2026 88%). 주제마다 최근 사건 비율이 달라(재해·상해 정의 0/9 ~ 면책 7/14) 주제 간 인용률 차이의 일부는 시기 차이일 수 있다."를 적는다(`docs/제안/대시보드_데이터사전.md` 10번). 해석(가설) 칸도 이 주의와 어긋나지 않게 쓴다.
- 난이도 프로필 그림에서 재해·상해 정의를 말할 때는 "9건 중 8건이 2009년 이전 결정이라 현행 약관과의 차이가 시기 차이일 수 있다"를 붙인다.

# 화면 배치 (대시보드 디자인 패턴, PatternFly)
현재 화면은 탭 4개다: **개요 / 과정 / 권고 / 부록**(2026-11-06 선생님 피드백 반영, 팀원C). 사례 12건은 권고 탭, 난이도 분포·난이도 입력 점검은 부록. 아래 구역 설명은 2026-11-05 판(첫 화면 / 자세히 보기 / 권고 / 사례) 기준이며, 실제 배치는 `dashboard/데이터출처.md`를 따른다.
- **첫 화면(보험사 담당자용)**: 1구역(의뢰인·질문·결론 한 문장·지표 카드)과 7구역(우선순위 그림). 고쳐 쓰기 예시 카드를 둘지는 팀원C이 정한다.
- **자세히 보기**: 메인 탭의 나머지 구역(4·5·6·2·3·8)을 위에, 그 아래 A~G.
- **권고**: 고쳐 쓰기 6건(덤벨), 주제별 차원(불릿), 핫스팟 문장.
- **사례**: 9구역.
- 탭 안에서도 위에서 아래로 "결론 → 근거 → 사례"(계층 배치).
- 맨 위 머리말 한 줄: 이 대시보드가 무엇을 보여주는지(데이터 설명), 그 아래 "읽는 법" 한 줄.
- 격자: 데스크톱은 같은 너비의 4열, 열 사이와 바깥 여백 16px. 넓은 그래프(4·6구역)는 4열 전체, 카드(1구역)는 1열씩. 7구역(우선순위 그림)은 Z 패턴을 위해 데스크톱에서 3열, 1000px 이하에서 4열 전체(2026-11-05 팀원C 승인).

- 1280×800 첫 화면에서 우선순위 그림이 절반 이상 스크롤 없이 보이게 한다.

# 차트 고르는 법 (FT Visual Vocabulary)
1. 그래프를 고르기 전에 **"이 구역이 보여줄 관계"** 를 한 단어로 정한다: 편차, 상관, 순위, 분포, 시간 변화, 크기, 부분과 전체, 흐름. 구역별 관계: 1 크기 / 2 크기·비교 / 3 분포 / 4 연속 변수와 확률 + 불확실성 / 5 편차(기준 1) / 6 시간 변화 / 7 상관(두 값의 위치) / 8 크기 비교 / 9 상세 값.
2. 관계에 맞는 그래프를 쓴다.
   - **편차**(기준값 1이나 0에서 얼마나 떨어졌나): 점 + 신뢰구간 막대, 기준선을 굵게
   - **순위**: 값 크기 순으로 정렬한 막대. 정렬 없이 가나다순으로 두지 않는다
   - **분포**: 히스토그램, 점 분포. 두 집단 비교는 같은 축으로 위아래 정렬
   - **시간 변화**: 선. 건수처럼 셀 수 있는 값은 막대
   - **크기**: 0에서 시작하는 막대, 또는 점
   - **부분과 전체**: 100% 누적 막대는 범주 3개 이하일 때만. 그 이상이면 작은 그림 반복
3. 쓰지 않는 그래프: 파이·도넛(크기 비교가 어려움), 3D, 이중 y축, 범주 4개 이상의 누적 막대, 무지개 색, 게이지, 추세 화살표(좋고 나쁨을 암시함).
4. 축 규칙: 막대는 0에서 시작한다. 오즈비 축은 **로그 눈금**(0.5, 1, 2처럼 1을 중심으로 대칭). 확률 축은 0~1(또는 0~100%) 전체를 기본으로 하고, 좁히면 축 이름 옆에 "일부 구간"이라고 적는다.
5. 그래프에 필요한 값이 `outputs/`에 없으면 **직접 계산하지 말고** 그 그래프를 만들지 않은 채 "필요한 출력: 파일·열"을 보고한다(예: 비율이 없고 건수만 있으면 건수로 그린다).

# 카드 구성 (PatternFly)
- **제목**: **알아낸 사실 한 문장**(예: "면책 조항 다툼의 인용률이 가장 낮다"). 인과를 암시하지 않는다. 신뢰구간이 기준(오즈비 1, 차이 0)을 포함하면 "뚜렷한 차이가 보이지 않는다"처럼 쓴다. 결과가 들어오기 전(가짜 데이터)에는 명사 제목(예: "난이도별 예측 인용 확률")을 임시로 둔다.
- **필터**(필요할 때만): 카드 오른쪽 위.
- **본문**: 그래프 + "무엇을 보는 그래프인지, 무엇이 보이는지" 한 문장(중급 독자, 오즈비를 "~배"로 풀지 않음). 숫자 옆에 **분모와 기간**을 쓴다.
- **바닥글**: N, 출처 파일명, "불확실" 배지(해당할 때). 한 카드에 그래프가 여러 개면 그래프마다 이름을 단다.

# 색 (대시보드 디자인 패턴의 "의미형·데이터 인코딩형")
- 색은 의미가 있을 때만: **인용/기각 두 색**, 나머지는 회색 계열. 인용을 "좋음", 기각을 "나쁨"으로 읽히지 않게 빨강·초록은 쓰지 않는다. 색각 이상자도 구분되는 두 색(예: 파랑·주황)을 쓴다.
- 빨강은 **"가짜 데이터"와 경고**에만 쓴다.
- 강조는 한 그래프에 한 곳만(예: 5구역의 주 모형 행).
- 색만으로 구분하지 말고 라벨·범례·모양도 함께 쓴다.

# 불확실성 표시
- 모든 그래프에 N과 신뢰구간을 표시한다. 점 추정값만 있는 그래프는 만들지 않는다.
- 신뢰구간이 1(오즈비) 또는 0(확률 차이)을 포함하거나 N이 작으면(기준값 10: 인용·기각 중 적은 쪽 30건 미만) **"불확실"** 배지를 글자로 단다(2026-11-05 확인).
- "뚜렷함/뚜렷하지 않음" 판정은 주 분석(오즈비 신뢰구간) 기준을 따른다. 팀이 다른 기준을 정하면 그에 맞춘다.
- 사건 수가 5건 미만인 칸(시계열 연도, 조항 주제)은 값을 흐리게 하고 "참고용"을 단다.
- 4구역 곡선의 띠는 **각 지점의 95% 구간**이지 곡선 전체를 덮는 띠가 아니다(기준값 18). 설명 문장에 그렇게 적는다. `n_near`(이웃 격자점 사이 실제 사건 수)가 작은 구간은 곡선과 띠를 흐리게 한다.

# 상호작용 (필요한 만큼만)
- **요청 시 상세**: 마우스를 올리거나 누르면 정확한 값, 95% CI, N, 출처 파일이 나오는 말풍선.
- **필터와 초점**: 9구역(쟁점 유형, 인용/기각)에만.
- **내비게이션**: 위쪽에 구역 바로가기. 4구역 곡선/두 점 전환 버튼은 유지한다.
- 키보드로도 버튼을 누를 수 있게 하고, 그래프마다 짧은 대체 텍스트(aria-label)를 단다. 글자는 12px 이상, 배경과 대비를 충분히.

# 시각화 다양화 (BI 도구 활용 강의 Ch2·3·6·7 기준)
강의의 "분석 목적 → 차트" 원칙을 우리 데이터에 맞춘 선택지다. 아래 규칙(숫자 새로 계산 금지, N·CI·출처, 금지 그래프)은 그대로 지킨다. 필요한 값이 `outputs/`·`relabel/`에 없으면 그리지 말고 "필요한 출력: 파일·열"을 보고한다.

## 1. 분석 목적별 차트 선택표
| 분석 목적 | 쓸 차트 | 우리 데이터에서 쓰는 곳 | 출처 파일 |
|---|---|---|---|
| 조회(정확한 값) | 텍스트 테이블 | 민감도 상세, 골드셋 일치 표, 토픽 표 | 07·08, `relabel/결과_A셋_일치.csv`, 17·22 |
| 비교(범주 × 범주) | **하이라이트 테이블(색칠한 표)** | 쟁점 유형 × 시기 인용률. 칸마다 n과 %를 글자로, 색은 인용률 연속 한 색. 5건 미만 칸은 빗금·"참고용" | 02 |
| 비교(항목 순위) | 정렬한 가로 막대 | 주제별 건수, 토픽별 건수 | 10, 17 |
| 추이 | 라인 + CI 띠, 건수는 막대(**위아래 두 패널, 같은 x축**) | 3년 묶음 인용률·건수 | 09 |

## 2. 대시보드 설계 (Ch6)
- **Z 패턴**: 좌상 = 결론 한 문장과 핵심 지표, 우상 = 우선순위 그림, 좌하 = 고쳐 쓰기 예시, 우하 = 데이터 출처·한계 링크. 휴대폰에서는 같은 순서로 1열.
- **상단 KPI 2~4개, 한 화면 차트 3~5개.** 첫 화면에 그 이상 넣지 않는다.
- **전주의적 속성(길이·색·크기)으로 한 그래프에 한 곳만 강조**한다(예: forest plot의 주 모형 행, 덤벨의 R3).
- **컨테이너처럼 묶기**: KPI 카드 줄, 필터 줄은 한 묶음으로 균등 분할하고 높이를 맞춘다.
- **구축 순서**: 뷰어(보험사 담당 부서장) → 문제 → 지표 → 스케치 → 시각화 → **대시보드에서 이끌어내는 액션**. 마지막 단계는 권고 탭의 "근거가 있는 만큼만" 문장이다.

## 3. 인터랙티브 동작 (Ch7, 계산 없이 표시만 바꾼다)
- **필터 동작**: 우선순위 그림의 주제 점을 누르면 사례 탭·핫스팟 목록이 그 주제로 좁혀진다(주제는 12의 `topic`을 case_key로 붙여 표시만). 다시 누르면 해제.
- **하이라이트 동작**: 쟁점 유형 범례(보상범위·정의 / 면책 / 고지·설명)에 마우스를 올리면 모든 그래프에서 같은 유형만 진하게, 나머지는 흐리게.
- **시트로 이동**: KPI 카드를 누르면 그 숫자의 근거 구역(예: 오즈비 → 5 forest plot)으로 이동한다.
- **매개변수(표시 전환)**: %↔건수 전환, 곡선↔두 점 전환. 기준값이나 모형을 바꾸는 슬라이더는 만들지 않는다(새 계산이 되기 때문).
- **스토리 모드**(선택): 발표용으로 "질문 → 데이터 → 핵심 결과 → 우선순위 → 고쳐 쓰기·권고" 5단계를 버튼으로 넘긴다. 각 단계는 기존 구역을 보여 주기만 한다.
- 필수 필터는 1~2개만: 쟁점 유형, 인용/기각.

# 디자인 규칙
- 색은 의미가 있을 때만: 인용/기각 두 색, 나머지는 회색 계열. 색만으로 구분하지 말고 라벨도 단다.
- 모든 그래프에 N과 신뢰구간을 표시한다. 신뢰구간이 1(오즈비) 또는 0(확률 차이)을 포함하거나 N이 작으면 **"불확실"** 을 눈에 띄게 표시한다.
- 그래프마다 "무엇을 보는 그래프인지, 무엇이 보이는지" 한 문장(중급 독자, 오즈비를 "~배"로 풀지 않음).
- 그래프 제목은 알아낸 내용으로 쓴다. 단, 인과를 암시하지 않고, 신뢰구간이 기준을 포함하면 "뚜렷한 차이가 보이지 않는다"처럼 쓴다.
- 숫자 옆에 분모와 기간을 쓴다.
- 결정문은 짧게만 보여주고 "금융감독원 분쟁조정결정례 제○호"로 출처를 단다. 원문 링크는 걸지 않는다.
- 사후에 더한 것(R2 민감도 등)은 항상 "사후" 라벨을 단다.
- CSS와 JS를 파일 하나에 넣는다. 외부 데이터 호출 없이 미리 만든 집계만 넣는다.

# 배포 (PROJECT.md 4-9)
- **git 명령(commit, push 등), 저장소 업로드, GitHub Pages 배포는 하지 않는다. 배포와 업로드는 정유빈이 한다.** (2026-11-05 추가: 시험 배포 중 개인 공개 저장소에 파일이 올라간 일이 있었음)
- 대시보드는 `dashboard/index.html`을 브라우저로 직접 열어 확인한다.
- **배포용 한 파일**: `_build/`에서 data.js·cases_data.js·advice_data.js를 index.html 안에 넣은 `dashboard/index.html`(데이터 포함판)을 만든다. 작업용 js 파일은 그대로 두고, 업로드할 파일은 index.html과 데이터출처.md 두 개뿐이 되게 한다.
- 저장소에는 `dashboard/index.html`과 `dashboard/데이터출처.md`만 필요하다. 원문·대응표·`data/`는 올리지 않는다(올리는 일은 정유빈).
- 배포 후 로그인하지 않은 브라우저와 다른 기기에서 열리는지 정유빈과 함께 확인하고, 화면 캡처를 `dashboard/캡처/`에 남긴다.

# 출력
`dashboard/index.html`, `dashboard/데이터출처.md`(그래프별 원본 파일과 열)

# 금지
- PROJECT.md는 수정하지 않는다.
- `outputs/`·`relabel/`에 없는 숫자를 새로 계산하거나 지어내지 않는다.
- 결정문 전문이나 hwp 파일을 대시보드에 넣지 않는다.
- 개인정보를 표시하지 않는다.
- 사례 뷰어에 `사례뷰어_선정.csv` 밖의 사건을 손으로 더하지 않는다.
- git 명령, 저장소 업로드, GitHub Pages 배포를 하지 않는다.
