# 역할
확정된 결과로 사람이 읽을 글을 만든다. 새 분석이나 새 주장은 만들지 않는다.

# 먼저 읽기
`PROJECT.md` 6장(인용·출처), 7장. 계획서 v7의 10장(정성), 11-1(페르소나), 13장(발표 구성).

# 입력
`data/interim/cases.csv`, `data/interim/texts/`, `outputs/stats/`, `docs/수집근거표.md`, `docs/제외사유.md`, `data/raw/cases_summary/`(분쟁조정 사례 160건), `relabel/결과.md`와 `relabel/결과_*.csv`(골드셋·LLM 비교), `docs/issue_type_민감도_규칙.md`(R2), `docs/사례뷰어_선정기준.md`

# 작업 1: 정성 확인 → `outputs/qual/정성확인.md`
1. `ambiguity = 1`, `explained_duty = 1` 비율을 인용·기각으로 나눈 표. `= 2` 비율도 함께.
2. 대표 사례: (난이도 상위·인용 / 상위·기각 / 하위·인용 / 하위·기각)에서 **시드 42 무작위** 각 3건, 모두 12건. 판단 핵심 2~3문장 인용, 인용 여부, 난이도, 이유 한 줄. 가설에 맞지 않는 사례도 같은 분량으로. (대시보드 사례 탭 12건 `outputs/qual/사례뷰어_선정.csv`와는 **다른 표본**이다. 섞지 않는다.)
3. 고객이 이긴 사건을 "작성자 불이익(모호해서)"과 "설명의무 위반"으로 나눠 센다.
4. 조항 주제 상위 2~3개에서 어떤 문구가 다툼이 됐는지 정리한다.
5. 분쟁조정 사례 160건에 PROJECT.md 4-6-2 기준(자동차보험 제외)을 적용한 뒤, 담보 분포를 결정례와 **나란히**(합치지 않고) 비교한다. 제외한 사례 수도 적는다.

# 작업 2: 보고서·발표 초안 → `report/초안_<독자>.md`
페르소나는 요청에 적힌 것을 따른다. 없으면 먼저 묻는다.
| 페르소나 | 독자 | 규칙 | 쓰는 곳 |
| 초급 | 보험·통계 모름 | 중학생도 이해할 문장, 용어 먼저 풀기, "100건 중 N건", **오즈비 쓰지 않고 예측 확률로** | 발표 첫 장, 요약 |
| 중급 | 보험은 알고 통계는 낯섦 | 통계 용어에 한 줄 설명, 효과는 예측 확률로 | 대시보드 설명 |
| 전문가 | 둘 다 앎 | 방법·가정·신뢰구간·한계 정확히, 오즈비와 예측 확률 함께 | 보고서 본문, 질의응답 |

발표 구성(가이드: 질문 → 주요 결과 → 권고 순서, 정제 과정은 노션으로): 의뢰인과 질문 → 데이터와 범위(짧게) → 주요 결과(핵심, 1998~2026년 추이(분석 포함 기준, 시기에 따라 인용률이 크게 다름에 주의), 우선순위 그림, 정성 사례) → 라벨을 믿을 수 있나(골드셋 한 장) → 민감도와 한계 → 권고(근거가 있는 만큼만).

보고서 구성(`report/보고서_<독자>.md`):
| 장 | 내용 | 근거 |
|---|---|---|
| 1 의뢰인과 질문 | 의뢰인, 핵심 질문, 왜 이 질문인가 | PROJECT.md 1장 |
| 2 데이터 | 출처·수집일·이용 조건, 건수 흐름(전체 → 제외 → 157건), 제외 사유 | `docs/수집근거표.md`, `docs/제외사유.md` |
| 3 방법 | 난이도 지표, 라벨(코드북), 모형. **3-1 라벨 신뢰도(골드셋)**: ① 무작위 골드 30건 원래 값(가린 대조)과 최종 골드를 나눠 쓰고 라벨마다 일치율·카파·2×2 표 ② 챌린지 22건(약점 표본이라고 밝힘) ③ 규칙 vs LLM 비교와 "셋이 같아도 25%는 사람과 다름" ④ 쟁점 유형 정의 차이와 R2 ⑤ 쟁점 조항 확인(약 5/28 문구 문제). 위원회 판단 비교는 부록 | `relabel/결과.md`, PROJECT.md 4-8 |
| 4 주요 결과 | 결과마다 관찰 → 해석 → 권고. 핵심 결과, 시기, 우선순위 그림, 정성 | `outputs/stats/`, `outputs/qual/` |
| 5 민감도와 한계 | 필수·선택 민감도(R2는 "사후·탐색적"), 한계 전부 | `통계요약.md`, `relabel/결과.md` 7절 |
| 6 권고 | 근거가 있는 만큼만 | 4·5장 |
| 회고 | 막힌 곳과 해결, 다음에 바꿀 점. PROJECT.md 변경 기록에서 고른다 | PROJECT.md 10장 |

우선순위 그림 문장 규칙: 점수나 순위를 쓰지 않는다. "건수 많고 인용률 낮음 = 고객 오해" 같은 문장은 **해석(가설)** 으로만 쓰고, "위원회까지 올라온 사건 안의 비율", "노출량은 모름"을 함께 쓴다.
- 의뢰인: 보험사 소비자보호·상품(약관) 담당 부서장(PROJECT.md 1장).
- 주요 결과마다 **관찰 → 해석 → 권고**. 관찰에는 분모와 기간을 쓴다.
- 질의응답 3개 답변 초안을 붙인다: 수치는 어떻게 구했나 / 데이터에 없는 고객은 누구인가 / 분석 단위를 바꾸면 달라지나(PROJECT.md 4-9).

# 작업 4: 노션 초안 → `report/노션초안.md`
가이드 항목 순서로 쓴다: 문제 정의(도메인, 의뢰인, 핵심 질문, 고른 이유) / 데이터(출처, 이용 조건, 수집 기간, 건수, 제외와 한계 — `docs/수집근거표.md`, `docs/제외사유.md`) / 분석(지표 정의 `docs/코드북.md`, 방법, 주요 결과) / 대시보드(주소, 화면 구성, 도구) / 회고(막힌 곳과 해결, 다음에 바꿀 점 — PROJECT.md 변경 기록에서 고른다). 숫자 규칙은 작업 2와 같다.

# 작업 3: 문체 보정 → `report/보정본_<독자>.md`, `report/보정내역_<독자>.md`
- 번역투, 긴 문장, 과장("매우", "획기적으로"), 조사·띄어쓰기, 용어 통일을 고친다.
- 바꾼 문장 전/후 표(최소 10개)를 남긴다.

# 꼭 넣을 한계 (2026-11-04 추가, 쉬운 말로 바꿔도 지우지 않음)
- 쟁점 유형(R1)은 "처음 나온 조항" 기준이라 사람이 보는 실제 쟁점과 다를 수 있다. R2는 이 차이를 보려고 결과 보기 전에 정한 사후 민감도이며, R1의 오류 모양을 알고 만든 규칙이라 완전히 독립된 검증은 아니다.
- 난이도를 계산한 조항 문구 중 약 5/28이 실제 쟁점 약관 문구와 달랐다(측정 오차).
- ambiguity "명백하다(2)"는 규칙이 거의 잡지 못한다(적게 센 값).
- 챌린지 22건의 정답은 한 명(정유빈)이 정했다.

# 금지 (모든 작업 공통)
- PROJECT.md는 수정하지 않는다.
- git 명령(commit, push 등), 저장소 업로드, 노션·GitHub Pages 게시를 하지 않는다. 올리는 일은 정유빈이 한다(2026-11-05 추가).
- 사후에 더한 분석(R2 등)을 주 결과처럼 쓰지 않는다. 항상 "사후"라고 밝힌다.
- `outputs/stats/`에 없는 숫자를 만들지 않는다. 숫자 옆에 출처 파일명을 괄호로.
- 인과 표현(때문에, 영향을 줬다)을 결론으로 쓰지 않는다.
- 독자 수준이 달라도 **결론의 강도를 바꾸지 않는다.** 한계·불확실성 문구는 쉬운 말로 바꿀 수 있어도 지우지 않는다.
- 오즈비를 "가능성이 ~배"로 풀지 않는다.
- 결정문은 2~3문장만 인용하고 바꾸지 않으며, "금융감독원 분쟁조정결정례 제○호"로 출처를 적는다.
- 개인정보가 보이면 쓰지 않고 보고한다.
- 신청인의 질병·진단명·복용약·계좌가 들어간 문장은 인용하지 않는다. 위원회의 약관 해석 문장만 인용한다(PROJECT.md 4-9).
