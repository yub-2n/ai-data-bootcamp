# 역할
`decisions.csv`의 사건마다 분석용 라벨을 붙여 `cases.csv`를 만든다. 분석 전체의 뿌리라서 가장 조심한다.

# 먼저 읽기
`PROJECT.md` 3장(기준값 4·5·7·8·11·14), 4장 전체, 5장(열 이름), 7장

# 입력
(결정일은 `decisions.csv`의 조정일자(hwp)가 기준이다. `fss_details.csv`의 `decision_date`는 최근 몇 건에만 있으니 쓰지 않는다. PROJECT.md 4-6-1)
`data/interim/decisions.csv`, `data/interim/texts/*.txt`, `data/interim/fss_details_enriched.csv`, `data/interim/pilot_sample.csv`

`decisions.csv` 주요 열: 조정번호(+출처), 조정일자(+출처), 안건명, 주문, 신청취지, 당사자_주장, 신청인_주장, 피신청인_주장, 위원회_판단(+추출 방식), 결론, 붙임, 약관_조문_표기_수, 형식(hwp5/hwp3), 오류.
- 옛 결정(2000~2001) 일부는 **주문이 없다**. 그때는 `결론`과 "이에 주문과 같이" 문장으로 판정하고 `needs_review = 1`.
- 최근 결정 일부는 신청인·피신청인 주장이 나뉘어 있지 않다. 그때는 `당사자_주장`을 쓴다.
- `위원회_판단_추출 = 추정`인 건은 판단 범위를 사람이 한 번 확인한다.
- 약관 문구는 `붙임`뿐 아니라 기초 사실의 "보험약관" 항목, 판단의 "관련 약관 규정"에도 있다(PROJECT.md 4-2 ⑤).

# 두 가지 모드

## A. 파일럿 모드 (27건, 11/2~11/4)
목적은 **규칙을 정하는 데 필요한 분포를 보는 것**이다. 난이도는 다루지 않는다.
1. 주문 문장을 모두 모아 **표현 유형별 건수표**를 만든다(인용/일부 인용/기각/각하·취하/기타 후보).
2. 판단 부분과 주장 부분에서 각각 약관 조항 추출을 시험하고 **추출 비율**을 계산한다(PROJECT.md 4-2 규칙, 법령 조문 제외).
3. 추정 분석 사건 수 = 445 × 보험 비율 × 본안 비율 × 변환 성공률 × 조항 추출·문구 확보 비율. **판단 기준과 주장 기준을 따로** 계산한다.
4. `explained_duty`, `ambiguity` 후보 문장을 뽑아 사람이 판정할 수 있게 표로 만든다(문장, 자동 판정, 사람 판정 칸).
5. 쟁점 유형 후보 범주(2~3개)와 조 제목 목록을 정리한다.
5-1. **자동차보험 판정 시험**(PROJECT.md 4-6-2): 파일럿 27건과 `auto_candidate = 1`인 게시물의 본문(기초 사실의 보험 종목, 쟁점 담보)으로 `is_auto`를 판정하고, 판정 근거 문장을 표로 남긴다.
6. 파일럿 결과를 `docs/파일럿_라벨보고.md`로 쓰고, 주 분석 전환 기준(60% AND 100건)에 따라 **판정 결과만** 적는다.
7. 팀원B에게 넘길 파일 `data/interim/pilot_for_difficulty.csv`를 만든다: `case_key, clause_ref, clause_level, clause_text, issue_type(후보)`만. **`cited`, 시기, 결과 관련 열은 넣지 않는다.**

## B. 본 모드 (전체, 11/5~)
PROJECT.md 4-8이 채워진 뒤에만 실행한다.
1. 4-1 판정표로 `cited`를 붙인다. 근거 문장을 `evidence_snippet`에 남긴다.
2. 4-2·4-3 규칙과 확정된 추출 위치(판단/주장)로 쟁점 조항을 추출한다. 다른 위치 버전도 민감도용으로 함께 저장한다.
2-1. 4-6-2 기준으로 `is_auto`를 판정하고, `is_auto = 1`은 `exclude_reason = "자동차보험"`으로 제외한다(건수 기록).
2-1-0. **`data/interim/texts/`는 `decisions.csv`에서 `오류`가 비어 있는 행의 파일만 읽는다.** 배포용(보호) 문서 19건은 1차 변환 때 안내문만 든 짧은 txt가 남아 있는데, 이것을 본문으로 읽으면 안 된다(지우지 말고 건너뛴다).
2-1-1. `decisions.csv`의 `오류`가 "배포용(보호) 문서"인 건은 `exclude_reason = "배포용 문서"`로 제외한다. 보호를 풀거나 다른 방법으로 본문을 얻으려 하지 않는다.
2-1-2. `주문`이 비어 있는 옛 결정은 `결론`("이에 주문과 같이" 앞뒤 문장 포함)으로 `cited`를 판정하고 `needs_review = 1`.
2-2. 결정례가 아닌 게시물("금융분쟁조정 사례집(보험)", nttId 64709)과 hwp가 아닌 첨부(pdf, tif)는 `exclude_reason`을 적고 제외한다.
2-3. `decision_date`는 hwp 조정일자에서 가져온다. 없으면 `fss_details.csv`의 `year`(조정번호 연도)로 구간만 정하고, 그것도 없으면 등록일 연도를 쓰고 `needs_review = 1`.
3. `decision_date`로 `period`(1999~2009 / 2010~2016 / 2017~2026)를 붙인다. 4-8의 구간 합치기·제외 판정을 따른다.
4. 4-4 규칙으로 `explained_duty`, `ambiguity`를 붙인다.
5. 4-5 확정 범주로 `issue_type`을 붙인다.
6. 4-6 규칙으로 중복을 제거한다.
7. **제외 사건 점검**(기준값 11): 분석 포함 vs 제외(사유별)의 인용률과 시기 분포를 표로. 난이도는 쓰지 않는다.
8. **대조용 표본**: 파일럿에 쓰지 않은 사건 중 시기별로 고르게 무작위 20건(시드 42)을 뽑아 `docs/대조표본.csv`로 만든다(원문 위치와 자동 라벨 포함).

# 출력
`data/interim/cases.csv`, `docs/제외사유.md`, `docs/파일럿_라벨보고.md`, `data/interim/pilot_for_difficulty.csv`, `docs/대조표본.csv`

# 금지
- 4-8이 채워지기 전에 본 모드를 실행하지 않는다.
- 결과를 보고 규칙을 바꾸지 않는다. 안 맞으면 "규칙 변경 제안"만.
- 난이도나 통계 결과를 보지 않는다.
- 근거 문장 없이 판정하지 않는다. 애매하면 `needs_review = 1`.
- 당사자 실명 등 개인정보가 보이면 저장하지 않고 보고한다.
