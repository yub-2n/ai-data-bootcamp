# 역할
결정례 445건을 받아 텍스트와 표로 바꾸고, 수집 과정을 기록한다. 새로운 수집 방법을 만들지 않고 정해진 스크립트만 쓴다.

# 먼저 읽기
`PROJECT.md`의 3장(기준값 2·3·6·7), 6장(수집·저작권 원칙), 7장

# 입력
- 스크립트: `fss_collect.py`(목록·상세·표본·다운로드), `hwp_batch.py`(hwp → 텍스트·CSV)
- 확인 결과(사람이 준 것): robots.txt, 금감원 저작권 정책

# 할 일
1. **수집근거표** `docs/수집근거표.md`를 아래 형식으로 만든다. 사람이 확인한 내용만 적고, 확인 못 한 칸은 "미확인".
   | 대상 | 확인일 | 확인 내용(원문 인용) | 결정 | 조건 |
   대상: 결정례(445건), 분쟁조정 사례(160건), 표준약관 3종.
2. 사람이 요청한 단계만 실행한다. 순서: `python3 fss_collect.py list` → `detail` → `sample` → `download --target pilot` → (승인 후) `download --target all`.
   - 각 단계 후 터미널 출력의 핵심(건수, 실패, 사이트 표시 총 건수)을 보고하고 **멈춘다.**
3. 변환: `python3 hwp_batch.py data/raw/decisions data/interim` 실행. 한글 3.0 파일은 LibreOffice가 있어야 변환된다(없으면 "LibreOffice 설치 필요"로 기록되니 사람에게 알린다). `sample`은 `data/raw/`를 고치지 않고 `data/interim/`에 쓴다. 이미 있는 파일럿 표본은 다시 뽑지 않는다.
   - 파일 이름 앞의 `nttId`를 `fss_details.csv`와 연결할 수 있게 `decisions.csv`에 `nttId` 열이 있는지 확인한다.
4. **파일럿 보고**(27건): 시기 구간별로 아래 표를 만든다.
   | 구간 | 파일 수 | 변환 성공 | 성공률 | 파일 형식(hwp/hwpx/pdf) | 결정일 확인 | 붙임 약관 있음 | 비보험 건 |
   - 변환 실패 파일은 `docs/변환실패.md`에 파일명과 오류를 적는다.
5. 전체 수집 후: 총 건수, 시기별 건수, 실패 목록, 형식별 개수를 보고한다.

# 출력
`docs/수집근거표.md`, `data/raw/*`(스크립트가 저장), `data/interim/decisions.csv`, `data/interim/texts/`, `docs/변환실패.md`, `docs/파일럿_수집보고.md`

# 금지
- 403/429가 나오거나 스크립트가 멈추면 **다시 시도하지 말고** 보고한다. 우회(다른 주소, 다른 User-Agent, 간격 줄이기)하지 않는다.
- 요청 간격을 3초보다 줄이지 않는다.
- 작성자·담당자 이름, 이메일, 전화번호를 저장하지 않는다.
- `data/raw/`의 파일을 수정·삭제하지 않는다.
- 변환이 안 되는 파일을 추정으로 채우지 않는다.
- 법적 판단("합법이다")을 하지 않는다.

# 끝나면
4줄 요약(한 일 / 처리 건수 / 실패·제외 / 불확실한 점) 후 멈추고 승인을 기다린다.
