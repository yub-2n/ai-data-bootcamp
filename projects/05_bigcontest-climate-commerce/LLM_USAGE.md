# LLM(Claude) 활용 기록

대회 규정: LLM을 활용하면 "구체적인 활용 방법 및 분석 과정에 대한 설명자료"를 제출해야 합니다.

## 사용 개요

팀 AOA는 분석 전 과정에서 Anthropic의 Claude를 보조 도구로 썼습니다. 코드 작성과 실행, 결과 점검, 자료 조사, 문서 정리를 Claude에게 맡겼고, 분석 방향·기준값·채택 여부는 팀원이 정했습니다. Claude가 낸 숫자는 팀원이 직접 다시 실행하거나 다른 방법으로 다시 계산해 확인한 뒤 썼습니다. 아래 "작업 기록"에 날짜 순으로 무엇을 시켰고, Claude가 무엇을 했고, 사람이 어떻게 확인했는지를 적었습니다.

### 1. 사용한 도구

| 도구 | 쓴 사람·위치 | 주로 한 일 |
|---|---|---|
| Claude Code (Anthropic) | 유빈 컴퓨터 | 전처리·분석 코드 작성과 실행, 재현 검증, 독립 재계산, 그림, 문서 수정 |
| Claude 대화 (Cowork, 클라우드 작업 공간) | 유빈 | 에이전트 결과 교차 점검, 외부 자료 조사(기상청·공공데이터포털·보도자료), 출처 메모·인수인계 문서 작성, 일부 재계산 |
| Claude Code | 팀원A 컴퓨터 | 외부 자료 정리(30년 강수, 상가정보 2025), 예측 모델·폭염·우선순위 코드, 진행정리 |
| Claude | 팀원B | 코드 재실행, 호우 특보·풍수해보험 자료 정리, 공휴일 달력 작성 |

### 2. 단계별로 Claude가 한 일과 사람이 한 일

| 단계 | Claude가 한 일 | 사람이 한 일 |
|---|---|---|
| 데이터 점검·전처리 | 카드·SK·기상·방문자 파일 구조 점검, 전처리 코드(src/prep.py)와 검증 숫자 대조(run_check.py) | 제외 업종과 업종 7그룹 확정, 외지인 정의 결정 |
| 외부 데이터 | 자료 후보·출처 조사, 출처 메모 작성, 파일 형식·MD5 확인 | 기상청·공공데이터포털·보도자료 원본을 직접 내려받음, 사용 여부 결정 |
| 호우 분석 | 이벤트 스터디 코드(event_study.py), jackknife·lead test·placebo, 금액 환산·반복성·50mm 비교 | 30mm 기준·사건 정의·연휴 제외 규칙 결정, 택시 처리 결정 |
| 모델·폭염·우선순위 | 예측 모델(사건 하나씩 빼고 검증), 폭염 분석, 우선순위 점수·민감도 | 가중치(제안값)·상권 단위 결정, 우선순위 기본안 변경 결정 |
| 보험 설계 | 발동 빈도(30년), 보험금 범위, 기준 위험, 풍수해보험 대조 | 발동 기준·대상 지역·영업이익률(12.6%) 결정 |
| 교차 확인·확장 | SK 구조, 관광공사 방문자 교차 확인, 5개 지역 유형별 추정 | 유형 기준과 추정 가능 기준을 결과 보기 전에 정함 |
| 발표 준비 | 그림 7개(figures.py), 분석 요약표 | 그림 확인, 제목·표현 결정 |

### 3. 사람이 결과를 확인한 방법

- **사람이 직접 실행:** 유빈이 본인 컴퓨터(Mac, Python 3.9)에서 코드 13개 전부와 노트북 3개(04~06)를 직접 실행해 기대값과 모두 일치함을 확인(코드 7개 run_check, event_study, rain_followup, model, heat, priority, aws_check와 노트북은 2026-10-16·10-22, 나머지 6개 rain_freq, insurance, sk_structure, visitor_check, regions, figures는 2026-10-22). 팀원B이 본인 컴퓨터(Windows)에서 event_study.py(2026-10-15)와 rain_followup.py(2026-10-20)를 실행. 팀원A은 직접 실행 기록 없음(2026-10-22 윈도우 재현은 Claude가 실행하고, 팀원A은 그림 7개를 직접 열어 확인하고 판정 표를 읽음).
- **다른 방법으로 다시 계산:** 핵심 숫자 8개를 원래 코드를 쓰지 않고 새로 짠 계산으로 다시 구해 점추정이 모두 같음을 확인(2026-10-22). 이 중 30년 호우 빈도와 점포 수는 다른 자료 경로·방법으로 확인한 독립 확인. 2026-10-22 교차검증 ②에서는 유빈이 팀 코드와 답이 없는 폴더를 만들어 새 Claude Code 세션이 방법 설명만 보고 다시 계산하게 함: 사건 수·표본·평소 날·점포 수는 일치, L·N5는 명세서에 없던 규칙 하나(연휴로 뺀 사건의 전날에도 L1을 붙이는지) 때문에 소수 첫째 자리가 달랐고 그 규칙만 맞추면 구간까지 같음.
- **여러 환경에서 재현:** 같은 코드를 4개 환경(유빈 Mac, 팀원B Windows, 팀원A Windows, 클라우드)에서 실행해, 점추정은 모두 같고 무작위 추출 구간의 끝값만 0.5%p 안에서 다름을 확인(2026-10-22 팀원A 윈도우 Python 3.14 재현 포함: 스크립트 12개·노트북 3개 일치, event_study 1개 구간 끝값 0.4%p 차이).
- **Claude끼리 교차 점검:** Claude Code의 보고를 Claude 대화가 다시 확인(숫자 대조, 그림 직접 열어 보기). 이것은 사람의 검증이 아니므로 작업 기록의 "사람이 검증한 방법" 칸에는 적지 않았습니다.

### 4. Claude의 결과를 고치거나 버린 예

| 무엇 | 처리 |
|---|---|
| 택시 업종 비중 "약 1~2%" | 다시 계산해 0.23%로 정정 (10/18~19) |
| AWS 400과 서울 108의 30mm 날 수가 뒤바뀌어 기록됨 | 원본으로 다시 세어 정정 (10/22) |
| "독립적으로 재계산"이라는 과장 표현 | 같은 코드를 다시 돌린 것이라 표현을 낮춤 (10/18) |
| "2025년 하반기는 30년 중 호우가 가장 잦은 시즌" | 춘천만 맞고 서울은 공동 1위라 고침 (10/22) |
| 단순 비교(호우일 ÷ 맑은 날) 재현 실패 | 규칙을 맞을 때까지 바꾸지 않고 결과에서 뺌 (10/22) |
| 우선순위 기본안 변경 | 결과를 본 뒤 바꾼 규칙임을 기록에 밝힘 (10/21) |
| 가설 "강남은 낮 시간 비중이 크다" | 결과와 달랐지만 가설을 바꾸지 않고 그대로 보고 (10/22) |

### 5. 외부 서비스(Claude)로 보낸 데이터 범위

- ① Claude 대화(Cowork, 클라우드 작업 공간)에는 카드 데이터1·데이터2 원본 파일 전체, SK 파일 10개(연령 7·12월, 시간대 7·12월, 요일 7~12월), 레이아웃·정의서 엑셀, 관광공사 방문자·공휴일 CSV, 기상청 ASOS 7개 지점과 강남 AWS 자료가 올라가 읽혔음(SK 연령·시간대 8·9·10·11월 파일은 올라가지 않음). 상가정보는 서울·강원 파일만 올라감(2026-10-18).
- ② Claude Code(유빈 컴퓨터)는 원본을 컴퓨터 안에서 코드로 읽고, 실행 결과로 출력된 집계 숫자와 일부 행 미리보기만 대화에 들어감(파일 전체를 올리지 않음). 출력된 행 수준은 따로 기록하지 않았음.
- ③ 팀원(팀원B, 팀원A)의 Claude에는 공유 묶음(코드, 문서, 기상·방문자·공휴일 CSV)을 줌. 카드·SK 원본은 묶음에 넣지 않았고, 각자 받은 파일로 실행함.
- ④ 팀원A의 Claude Code는 팀원A 컴퓨터 안에서 카드 데이터1·2, SK 18개, 상가정보(2025 3개, 2026), 30년 강수, 특보 CSV, ASOS, 관광공사, 공휴일 달력을 읽었고, 대화에는 집계 숫자와 일부 행 미리보기(머리글과 앞 몇 줄)만 들어감. 웹 확인은 기상자료개방포털 지점정보·ASOS 자료 페이지, 공공데이터포털 상가정보 페이지 열람(데이터 업로드 없음).
- ⑤ 2026-10-22 팀원A → 유빈 Claude 대화: 팀원A 쪽 묶음(코드 4개, 노트북 3개, 업종연결표, 30년 강수 폴더, 특보 CSV, 풍수해보험 PDF, 출처 메모, 문서). 카드·SK·상가정보 원본은 보내지 않음.
- ⑥ 팀원B의 Claude(Cowork, 클라우드 작업 공간)에는 카드 데이터1·데이터2 원본 파일 전체, 카드 레이아웃 엑셀, SK 요일 파일 6개(7~12월)·시간대 7월 파일·유동인구 정의서, 춘천 ASOS(기상자료개방포털 내려받기), 팀 공유 묶음(코드, 문서, 관광공사 방문자·공휴일 CSV, ASOS 7개), 기상특보 CSV(2025-07~12), 풍수해보험 보도자료 PDF, 상가정보 2026-06 zip 전체(전국 17개 시도), 팀원A 쪽 결과물(priority.py, 노트북 06, data_additions.md), 10/22 전달 묶음 2개와 AOA 인수인계 묶음(카드·SK 원본 없음)이 올라가 읽혔음. 상가정보 2025 파일, SK 연령·시간대 8~12월 파일은 올라가지 않음 (2026-10-22 팀원B 확인).
- ⑦ 개인 식별 정보는 없는 집계·격자 자료로 알고 있음(미확인).

### 6. 이 기록을 읽는 법

- 작업 기록은 날짜 순입니다. 항목마다 시킨 일, Claude가 한 일(방법), 사람이 검증한 방법, 수정·기각한 부분, 관련 파일을 적었습니다.
- "사람이 검증한 방법"에는 팀원이 실제로 한 일만 적었습니다. Claude가 한 확인은 이 칸에 넣지 않았습니다.
- 코드와 실행 순서는 기타 자료의 README, 덧붙인 변수와 외부 데이터 출처는 docs/data_additions.md와 data/external/SOURCES_*.md, 분석 결과 요약은 docs/분석요약.md에 있습니다.

## 작업 기록

### 2026-10-13 · 카드 데이터2 업종 묶음 제안 (읽기 전용)
- 시킨 일: 카드 데이터2의 83개 업종(제외 7개 뺌)을 6개 그룹(방법 A)과 10개 그룹(방법 B)으로 묶는 방법을 제안하고, 지역(강남·춘천)별 일별 결제 건수를 비교.
- Claude가 한 일(방법): 업종 이름과 성격(실내/야외, 생필품, 서비스/상품 여부)만 보고 묶음을 만듦. 비(강수) 반응은 보지 않음. 그룹별 일평균, 하루 최소, 30건 미만 일수를 계산. 이름만으로 성격이 불분명한 업종(기타식품, 기타요식, 기타유통, 기타의료, 체인점, 전용매장 등)은 "미확인"으로 표시.
- 사람이 검증한 방법: 유빈이 Claude의 제안을 읽고 추천대로 진행하기로 함. 숫자를 사람이 따로 계산하지 않음.
- 수정·기각한 부분: 방문판매/다단계판매는 판매 방식이라 업종 성격과 맞지 않아 "애매"로 표시하고 원래 자리를 유지함. 그룹 크기와 일별 건수 기준으로 방법 A를 추천했으나 채택 여부는 미정.
- 관련 파일: `신한카드_빅콘테스트2026_데이터2.txt` (읽기만 함), 계산 스크립트 `scratchpad/group_stats.py` (프로젝트 폴더 밖, 임시).

### 2026-10-15 · 전처리 복사본 확인, 호우 사건 모형 점검, placebo 실행
- 시킨 일: 새 작업 폴더로 옮긴 `src/prep.py`, `src/run_check.py`가 온전한지 확인.
  춘천 10/10 사건 점검, 10/10 사건 제외 추정, 사건 이전 날(L1~L3) 검정과
  겹침 점검, 맑은 날 비율 재검증, 서울 10/10 사건 변형 모형, placebo 1,000회.
- Claude가 한 일(방법): `run_check.py`를 실행해 항목별 일치 여부를 코드로 셈
  (일치 50, 다름 0). 주 모형(OLS, HAC maxlags=3)과 계수 3,000번 추출 구간,
  사건 구간 제거(jackknife), lead test, 가짜 사건 5개를 균등 추출한 placebo를
  파이썬으로 계산(시드 2026). 스크립트는 저장하지 않고 표준입력으로만 실행.
- 사람이 검증한 방법: 분석 자문용 별도 Claude 대화가 에이전트의 보고 숫자를 대조함(N=L−R5 관계 확인, jackknife 재현 등). 이는 사람이 아닌 Claude의 교차 점검이며, 일부는 같은 코드를 다시 돌린 것이라 완전히 독립적인 재계산은 아님. 이 시점에는 팀원의 직접 검증을 하지 않음(이후 항목 참고).
- 수정·기각한 부분: 맑은 날 비율 기준값 0.858, 0.949는 폐기했다가 보류를 거쳐 "재현됨"으로 변경(빈칸 채운 날을 맑은 날에 포함하는 정의로 ±1%p 이내). 이전 placebo 표는 쓰지 않음. 서울 10/10 사건은 변형 모형을 민감도로만 제시.
- 관련 파일: `src/prep.py`, `src/run_check.py`, `CLAUDE.md`(6장 답변 형식 추가),
  `전처리_명세서.md` (읽기만 함)

### 2026-10-15 · 팀원B 코드 재실행 검증 (event_study.py)
- 시킨 일: README_실행가이드.md 순서로 event_study.py를 본인 PC에서 재실행하고,
  보고값과 다른 항목의 원인 확인
- Claude가 한 일(방법): 실행 폴더 점검(압축 해제 때 이름이 깨진 ASOS 파일 7개를
  원본 이름으로 다시 넣음), 실행 명령 안내. 클라우드 환경(Py3.13, numpy 2.5.3,
  statsmodels 0.15.0)에서도 같은 코드를 실행해 대조(일치 91, 다름 2).
  시드 4개로 다시 돌려 다른 2개가 시뮬레이션 오차(±0.3%p) 범위임을 확인
- 사람이 검증한 방법: 내 PC(Windows, Python 3.11.15, numpy 2.4.6, pandas 3.0.3,
